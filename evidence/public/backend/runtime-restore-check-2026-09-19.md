# Essai du script de restauration runtime — 19 septembre 2026

Le dump et les fichiers de [la sauvegarde runtime synthétique](runtime-backup-check-2026-09-19.md) ont été restaurés avec `ops/restore-runtime.ps1 -AllowDatabaseReplace` dans une base fraîche `palimpseste_runtime_restore_test` et un stockage neuf `C:\ProgramData\Palimpseste\runtime-restore-test-artifacts-v2`. Le script a terminé sans erreur. La base restaurée contient **4 lignes `public.artifacts`** ; un contrôle indépendant a vérifié **10/10 fichiers copiés** contre les SHA-256 du manifeste. `icacls` sur un fichier restauré montrait `PalRuntimeSvc:(M)` et les droits complets pour l'utilisateur opérateur, Administrateurs et SYSTEM.

Deux premières passes ont servi à corriger des défauts concrets. La première a échoué avant mutation à cause de `TrimEnd('\\', '/')` dans le contrôle du chemin de staging ; le littéral PowerShell a été corrigé. La seconde a révélé des ACL vides sur les fichiers enfants, corrigées par application des droits à chaque fichier et dossier. Lors de cette seconde passe, **le script de test**, qui construisait mal sa chaîne de connexion via `DbConnectionStringBuilder` sous PowerShell, a pointé vers la base synthétique source et y a restauré son propre dump ; la base cible fraîche est restée vide. Le test final a passé explicitement host, port, base cible, utilisateur et mot de passe sans journaliser ce dernier.

Cette preuve couvre le dump synthétique, les empreintes et l'accès fichiers après restauration. Elle ne couvre pas une restauration d'exploitation avec utilisateurs connectés, un appel Luna ni une acceptation humaine. Les données et mots de passe de test restent hors Git.
