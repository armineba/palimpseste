# Limite quotidienne de l'application retirée

Le plafond de nouvelles générations par principal et au total sur 24 heures a été retiré des deux parcours de création de jobs : transmission d'un dessin et diagnostic de plan par créateur. Un dessin conservé localement après le refus « Votre quota quotidien de générations est atteint » peut être renvoyé avec **Transmettre** ; l'idempotence de la capture permet de garder la même trace. La migration `004_generation_quota.sql` et son index peuvent rester dans les bases existantes, mais ne pilotent plus l'admission des jobs. Les anciennes variables `PALIMPSESTE_GENERATIONS_PER_PRINCIPAL_24H` et `PALIMPSESTE_GENERATIONS_GLOBAL_24H` ne sont plus lues par l'API.

Cette modification retire **uniquement la limite quotidienne propre au jeu**. Le compte Codex connecté sur le serveur garde ses limites de disponibilité et d'utilisation : si elles sont atteintes, Astra ou Luna peuvent toujours refuser ou retarder une génération. L'application ne déclenche aucun achat ni recharge ; elle ne peut pas vérifier ou modifier le réglage de recharge du compte ChatGPT. Le souhait de l'exploitant est de n'utiliser que l'abonnement actuel, sans achat de crédits ni recharge automatique. Le comportement du compte doit être vérifié dans son interface de facturation, indépendamment de l'API du jeu.

Le backend corrigé a été compilé dans la solution sans avertissement ni erreur ; la QA des contrats a passé **61/61**. L'API publiée sous `PalRuntimeSvc` a pour SHA-256 `1E530DAE4DB1680BBDB7E8388DF825D215C5BCF5B17DE50A7B5E4ACD4FA64B7C` ; son processus observé est PID `35728` et `/health/ready` a répondu 200. Le script enfant `ApiService.Child.ps1` a pour SHA-256 `3655615CF544B6E757F33FC61B773C83943935E06B0C70559B7B20E2EA2D1762`. **Aucune nouvelle capture HTTP réelle n'a encore été retentée** depuis cette publication. Les résultats ci-dessous concernent **l'ancienne implémentation**.

## Historique — ancien plafond applicatif

L'ancienne API admettait par défaut **3 nouveaux jobs par principal** et **12 nouveaux jobs au total** sur une fenêtre glissante de 24 heures. Les valeurs étaient configurables par `PALIMPSESTE_GENERATIONS_PER_PRINCIPAL_24H` et `PALIMPSESTE_GENERATIONS_GLOBAL_24H` ; le déploiement local avait porté le plafond joueur à **5**. Au moment du refus montré dans le jeu, **5 jobs joueur et 6 jobs globaux** ont été constatés. Ces valeurs expliquaient le HTTP 429, mais ne s'appliquent plus à la version corrigée.

Les deux points de création de jobs, capture de dessin et diagnostic de plan par créateur, utilisaient le même contrôle. Une transaction PostgreSQL en isolation `READ COMMITTED` explicite prenait un verrou consultatif commun, comptait les jobs créés dans les dernières 24 heures, puis insérait le job avant de relâcher le verrou par commit. Le rejet HTTP 429 `generation_quota_exceeded` survenait avant l'écriture des nouveaux artefacts. Le contrôle comptait les jobs admis, quels que soient leur état ou leur succès.

Un rejeu idempotent d'une capture déjà soumise renvoyait le job existant avant le contrôle ; reprendre ou réessayer ce job ne créait pas de nouveau job et ne consommait pas une nouvelle admission. La migration `backend/migrations/004_generation_quota.sql` avait ajouté l'index de lecture de cette fenêtre.

Cet ancien plafond **n'était pas une limite de crédits OpenAI**. Un même job pouvait entraîner plusieurs tentatives du fournisseur, et les appels à Codex hors de cette API n'étaient pas comptés. Il bornait les nouvelles demandes admises par l'application, sans garantie monétaire absolue.

Le worker utilisait déjà le compte ChatGPT présent sur le serveur, sans clé API. Le serveur ne dispose pas d'une interface fiable pour lire ou modifier le solde et le réglage de recharge de ce compte. L'ancienne mention « worker reste arrêté » ne décrit plus le service local actuellement déployé.

## Vérification du 20 septembre 2026

`dotnet build Palimpseste.sln -c Release -v:q` et `dotnet build tests/Palimpseste.Api.GenerationQuota/Palimpseste.Api.GenerationQuota.csproj -c Release -v:q` : succès, 0 avertissement et 0 erreur chacun. Le test utilise exclusivement la base locale `palimpseste_test` et crée puis supprime un schéma aléatoire isolé. Vingt admissions concurrentes avec plafonds de test 2/principal et 3/global ont produit exactement 3 jobs engagés ; aucun principal n'a dépassé 2. Un job vieux de 25 heures et une transaction annulée n'ont pas consommé de place ; un principal a été refusé par le plafond individuel et un autre par le plafond global. La sortie publique est sous `evidence/public/backend/generation-quota-2026-09-20.md`.

Le test vérifie la transaction et la concurrence réelles en PostgreSQL. Sa table isolée ne teste pas l'index de la migration 004 ; la présence de cet index a été contrôlée séparément dans `palimpseste_lab` après application. Il ne vérifie pas une requête HTTP complète : le lancement de l'API privée de test avait été refusé par la revue automatique avant exécution. Les chemins idempotents ont été revus dans le code, sans essai HTTP après cette modification.
